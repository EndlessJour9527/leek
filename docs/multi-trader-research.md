# 每日多交易员研究团队 v1

依据用户 2026-10-21 的要求：每天执行多个交易员的研究任务，共同推进收敛，而不是全队每天只研究一个候选。本文调整研究组织方式，不改变冻结策略、费用、数据完整性和实盘授权边界。

## 真实状态与能力边界

`research/trader_team.json` 注册 10 个研究席位。它们是有独立假设、代码版本、验证记录和模拟账户的策略线，不是 10 个已部署、全天在线的 LLM Agent。

当前仓库中 T01 MA120、T02 H001、T03 H002 有策略实现；T04—T10 是待开发研究席位，不可报告为已实现策略。`research.run_h002` 是现有批量入口，会顺序运行现金/买持/MA120/H001/H002对照，不是并行进程引擎。已知 DQ001 未解决时，不运行受影响样本的有效表现更新。旧成绩只能带原始数据等级和新增争议引用。

外部每日研究任务已设置在 UTC+8 晚间约19:00（包含周末）。仓库配置本身没有部署 Mac 常驻服务、没有新增已运行的 GitHub 定时工作流，也没有创建独立的10个自动交易进程。未来有可用并行工具时才并行执行并记录实际任务ID；没有则在同一任务内按角色推进多个工作项，如实报告执行方式。

## 每天的工作循环

研究取舍统一遵循[章程第一原则](research-charter.md#第一原则与每轮取舍)；下述为组织与记录方式，不再增加一套机制或审批清单。

1. **共享准备**：读取仓库最新PR/CI/实验登记、市场数据截点、已知冲突。数据只抓取和核对一次，问题按受影响数据/策略范围传播。优先修复能解锁最多席位的公共阻碍。
2. **按变化选择工作**：先复用席位登记和已有可信检查；只处理有新证据、变更或明确缺口的研究。10席位不是每日重跑或策略数量配额；未变项记 NO_NEW_EVIDENCE。未实现项按机制与信息价值决定是否投入，缺数据项按影响范围取证。
3. **并行可做的工作**：数据审计、均值回归假设、轮动数据契约、价值/事件的时点数据调查、短线成交模型等互不依赖，不因某一个510300数据争议全部停止。但依赖争议数据的收益计算仍阻断。
4. **独立账户、公平对照**：同一研究队列固定输入快照、时间窗口、成本和风险预算。各席位独立记账；现金和被动基准共享配置，不共享可用资金。不能把10个独立研究账户的资金汇总为一份真实资产。
5. **分组评估**：按策略周期和数据域分别比较，不用短线胜率去评价长线价值策略。记录净收益、回撤、平均风险暴露、已平仓胜率与样本数、平均盈亏、净期望、压力成本、相对基准和收益集中度。相似策略和重叠ETF不是新的独立证据。
6. **复盘和分配研究资源**：按事前标准区分实现缺陷、证据不足和经济机制失败；低增量或高成本方向降优先/归档并保留记录，不由一次失败推断永久无效；有研发证据的进入新的独立验证；资料不足的明确待证据。优先级由新增信息、可复现性和互补性决定，不能只追逐当日收益第一名，更不能自动加大资金。

周末没有当日交易时，运行历史验证、开源研究和工程测试。没有数据/代码/假设变化时复用原报告，并记 `NO_NEW_EVIDENCE`，不重复计算同一历史窗口假装前进。

## 多候选与尝试次数

- 取消“全队每轮最多一个新增候选”；改为**每个席位每轮最多一个预登记新候选**，不同席位可在同轮推进。
- 保留**每阶段8个新增候选的全队共享预算**，不是每席8个。所有失败和放弃的尝试都计数；已经登记的实验不因换席位而获得新身份。
- 参数/阈值/仓位/执行规则变化均需新实验身份。修复数据解析与不改变经济行为的工程测试不算策略候选。
- 用完预算后作阶段复盘，登记下一阶段问题与预算，不静默重置计数或放宽验收条件。
- 2020—2025和已查看的2026样本是研发样本，不能重新命名为未见数据。多交易员意味着更多被尝试的假设，不意味着更强的统计证据。

## 数据与风控的独立否决

DQ001 的严格门槛继续生效，对所有依赖争议样本的席位和对照一致适用。第二来源断线不能绕过已发现冲突；不得靠放宽0.001误差容忍度或修改状态字段制造“解决”。必须保存独立来源、字段/复权口径与审查记录。

价值质量需要时点财务数据和历史证券池；事件策略需要实际公告发布时间；ETF轮动需要多标的同口径资料；打板需要足以支持封单排队/成交判断的盘中数据。日线价格、日线涨停不能替代这些证据。

组合层另建共享现金和风险总账，检查相关性、总敞口、集中度及冲突订单。不得将十个席位的买入建议简单相加，也不通过多数投票下单。

## 每日报告

沿用每日报告字段：`seat_id / strategy_version / work_completed / evidence_links / status / data_fingerprint / sample_role / metrics / blockers / next_step`。未变项引用原登记/报告，不重复抄写。仅在新登记或相关变化时补齐下列取舍字段（写入原实验协议或报告，不新建并行模板）：

- `mechanism_and_risk_bearer`：收益机制、付费/风险承担来源、证据或待证项；预测相关性与因果主张分开。
- `comparator_and_constraints`：最简单可比基准、实际暴露、信息可得时点、执行/成本/容量/尾部边界，链接已有输入与账本契约。
- `falsifier_and_stop`：评估前固定的反证、失败/保留标准、停止阈值、样本角色及累计尝试；区分错误实现、待证和机制失败。
- `increment_and_cost`：复杂模块相对简单版本的可测增量、研究维护成本；本轮复用检查、受影响回归及继续/降优先/归档理由。

允许状态：`RESEARCHED`、`IMPLEMENTED_TESTED`、`BACKTEST_COMPLETED_CONDITIONAL`、`REJECTED`、`NEEDS_MORE_EVIDENCE`、`BLOCKED_DATA`、`WAITING_IMPLEMENTATION`、`NO_NEW_EVIDENCE`。计划和源码测试不得写作回测已完成；未知指标为null，而不是0；报告没有合格赢家时就不选赢家。

M1/M2/M3阶段验收保持研究章程不变。收益/回撤改善、成本压力、未参与选择的数据和真实前向记录，比扩大策略数量更重要。任何阶段通过均不自动授权实盘。

## 实施顺序

当前增量只完成每日任务升级、10席位注册及治理测试；没有新策略绩效或新的模型并行运行证据。首先由共享数据职能核对DQ001，同时由其他席位独立推进规则定义与数据取证。之后逐个将已登记、有必要数据的策略接入共同回测入口。
