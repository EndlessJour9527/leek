## 实际读取与执行规则

两条 acquisition 路径使用同一裁决器。来源当期报价必须仍是审过的 **完整 20 个 Eastmoney/Tencent 值对**，所有其他日期与 OHLC 必须精确一致；缺格、额外冲突、原值修订、交易日不一致都拒绝。即使某家后来“修正”到相等，也需要新审计版本，不悄悄继承旧批准。

规范化输出从东方财富副本开始，**只替换这 20 个 OHLC 单元格**为原公开审计中已存在的获选值；非争议价格、成交量及原始文件不变。不比较或替换成交量。输出记录：

- `status: REVIEWED_SOURCE_PRECEDENCE`
- `differing_cells: 20`、`resolved_cells: 20`、`unresolved_cells: 0`
- 原始价格文件相对名与 SHA256、采集 URL 与原始响应字节数
- 规范化 bars 哈希、证据/审计哈希及真实先前证据提交

严格执行器、兼容执行器、H002/H003 和统一 preflight 均走共同验证。实际执行前重新读取私有原始文件，校验哈希/HTTPS 供应商路由/证券与调整参数，重新解析两家全部价格，复现完整规范化 bars，并重读、校验和解析分红文件。删除分红、篡改一格价格/成交量、缺少原件、伪造来源或更改裁决 metadata 均不会进入策略计算。原严格 `crosscheck` 仍拒绝任何一跳差异，未添加容差。

**本范围只接受可重放的双源审查证据。** `--allow-single-source` 最多仍可收集一个明确降级的调查输入；它不能执行本范围研究。把裁决数据改标为旧 `MATCH` 或 `SECOND_PRICE_SOURCE_UNAVAILABLE` 也不能绕过原件验证。
