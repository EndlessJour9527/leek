# 真实历史日线回测 v1

这是独立于旧合成回放入口的**真实历史、条件成交研究**：直接抓取行情服务的历史数据，复用主分支 `Ledger`，输出连续账户净值、逐笔交易、分红归因、逐年收益和成本压力结果。不连接券商，不使用真实账户，不自动调参或晋级实盘。

## 先冻结，再运行

`research/real_history_protocol.json` 已在查看本轮收益结果前提交。研究对象只选定 510300，2019 年预热，2020—2025 年连续账户回测；研究本金 50,000 元，每次进场参考账户净值 20%，100 份向下取整。不因发现盈利或亏损而改变这些参数。

比较零息现金、一次买入持有、MA120 单日确认、MA120 三日确认 H001。所有方案共用行情、时间窗口、费用和分红处理。压力情景重新执行完整账户模拟，而不是固定成交路径后简单扣双倍费用。

这不是全市场选股模型，也不是事先封存的样本外验证。研究池为事先选定的一个存续 ETF；不能从中推断其他个股、其他 ETF 或未来市场表现。

## 数据入口

```sh
# 在仓库根目录；Python 3.10+，仅标准库。
python3 -m unittest discover -s tests -v
python3 -m leek.history_data --output /tmp/leek-real-input
python3 -m leek.real_backtest --input /tmp/leek-real-input/dataset.json --output /tmp/leek-real-results
```

输出目录必须不存在。失败的下载目录保留实际取得的快照；重新抓取须选择新目录，不覆盖旧证据。用户 Mac 可运行同样命令，无需每天人工整理 CSV。网络请求有大小/时限/重试上限，访问失败即停止，不生成行情、不回退合成数据、不偷偷修改输入。

- 东方财富 `kline/get` 的 `fqt=0` 为主日线，字段包含原始 OHLC 与成交量；不使用基金净值替代二级市场成交价格。
- 腾讯 `fqkline/get` 必须返回不复权 `day`，分年获取并与主日线逐日比较日期和所有 OHLC，哪怕 0.001 元差异也会暂停。该一致性不是交易所原始记录认证，两个服务也可能共享上游。
- 上证指数交易日期作为额外日历检查；它只是交易日历代理，不是对交易所日历和标的历史交易状态的完整认证。
- 天天基金分红表自动解析「每 10 份」金额并除以 10。已知事件清单仅作为版本变化探测；公告历史与份额变化完整性仍不宣称已独立验收。检测到样本期内拆分/折算即拒绝，不删除事件后继续计算。
- 原始响应、URL、SHA-256、抓取时间和规范化数据保存在本地输入目录。CI **不上传原始行情和完整源网页**；只发布本项目的派生账户研究报告。数据服务的访问/使用许可仍需使用者遵守。

## 交易和记账规则

**时间顺序：**截至 t 日收盘的数据形成意图，最早 t+1 个列明交易日开盘尝试执行。预热期不持仓，不凭未来开盘价决定数量。信号元数据中的 17:00 为收盘后可得的研究假设，不是已核验的历史供应商发布时间。

**价格与成本：**成交参考原始开盘，加不利滑点，买价向上、卖价向下取到 0.001 元。基准佣金为 0.02%、最低 5 元、滑点 5bp；压力情景为 0.04%、最低 10 元、滑点 10bp。佣金取到分，滑点已嵌入成交价，不再重复扣除。这些是实验参数，**不是国元证券的实际费率**。

**资金与份额：**复用 Decimal 共享现金账本，无杠杆；按成交前一日已知净值/现金形成固定数量。资金或可卖份额不足时整笔拒绝且不扣费用，不用未来收益补足历史现金。每日收盘重新评估未成交条件。20% 是入场参考预算；开盘跳空和之后涨跌会改变实际暴露，不是自动控制在 20% 以内的硬仓位上限。

**分红：**登记日交易结束后锁定份额；除息日开盘前确认应收红利；发放日交易结束后转为可用现金。登记后卖出保留分红权利，除息日买入不获得该次分红，支付时不重复确认收益。采用显式的税前、无额外税费研究假设，不能当作个人税务处理结论。

**信号：**使用精确分数构造前向总回报序列 `TR[t] = TR[t-1] * (close[t] + dividend_ex[t]) / close[t-1]`。MA120 包含当日已经收盘的值；H001 连续三日高于均线进入 ON，连续三日低于均线进入 OFF，等于均线重置计数但保留状态。分红只在已发生的除息日进入序列，不重写历史信号。

**期末：**不人为按最后收盘价清仓；未平仓损益持续计入净值和回撤，未执行末日意图明确保留。终值不扣尚未发生的最终退出费用。

## 报告与调试

每个策略/成本情景输出一个 JSON，包含：

- 连续的 `daily` 净值、现金、持仓、应收、已实现/未实现交易盈亏、分红、成本、暴露、收盘回撤。
- `orders` 的信号日期、执行日期、固定数量、费用、拒单原因以及成交前后现金；`signals` 与末日未执行意图。
- `closed_trades`、`open_trades`，分红按登记日所在持仓周期归属，跨卖出/除息/到账也不丢失。已平仓净胜率只计最终扣费并归属分红的完整往返；未平仓浮亏不会藏在胜率分母外，因为它始终计入每日净值。
- 每天检查 `NAV - 初始现金 = 已实现交易盈亏 + 未实现交易盈亏 + 累计分红收入`；期末另核对所有持仓周期盈亏的合计。
- 全账户总收益、几何年化、最大**收盘**回撤、平均暴露、佣金/滑点、盈亏比相关指标、已平仓数量、年度连续收益。小样本胜率不是下一笔成功概率。
- 输入/配置/源码哈希。完整输入及实现一致时，双 Python 版本结果应逐字节一致。

新模块会改变旧回放的包源码指纹。旧检查点需要原版本代码，不能编辑哈希强制恢复。原合成回放入口仍拒绝真实数据，不删除它的安全边界。

## 当前不能从结果推出什么

日线开盘模型没有验证盘口排队、涨跌停时能否成交、实际容量、交易所历史状态或逐时点供应商修订。原始日线的高低价和全天成交量不用于开盘成交判断，避免偷看当天未来数据；这也意味着对成交能力存在明确限制。

数据跨源一致、记账对平、测试通过，分别证明不同事情；任何一项都不等于策略有稳定优势。单次回测优于买入持有也不等于风险调整超额收益，因为持仓暴露不同。自动策略晋级固定关闭。

下一步在同一框架内增加事先登记的市场分段、不同标的验证与前向纸面记录；不能反复用本轮已看过的窗口挑出漂亮参数。
